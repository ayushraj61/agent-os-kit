# Verification evidence

No checks have been run by this template. Populate commands from the actual project.

## Project checks
Record available unit, integration, lint/type, migration, and release checks with their scope and environment requirements. Do not assume a language or test runner.

## Execution records
For each run record task, date, revision/worktree state, environment, exact command, observed result/exit status, and relevant counts. Link CI artifacts when available. Redact sensitive data. Mark unavailable checks as blocked/unverified and explain the consequence. No sample PASS results belong here.

## Feature readiness
For the affected feature/environment, state which claims are evidenced: implemented, works locally, verified for the stated scope, and ready for the intended release. See [the evidence levels](guides/backend-delivery.md#make-progress-and-readiness-understandable). For each significant gap record user impact, next action, and whether it blocks the intended release. Unit-test success alone does not establish release readiness.
